**1. Agent Lightning v1.0：3500行轻量级代理强化学习框架，用真实代理框架训练智能体**
原题：Agent Lightning v1.0: A 3,500-Line Lightweight Agentic RL Framework for Training Agents with Real Harnesses
分类：Agent训练　推荐：⭐⭐⭐⭐（8.5/10）
来源：Microsoft Research　发布时间：2026-10-07
入选理由：轻量级Agent RL框架连接现有Agent与训练，3500行实现，无需重建，工程与Agent训练价值高。

**一句话结论**：Agent Lightning v1.0 通过 LLM 代理让部署时使用的同一代理框架直接参与强化学习，仅用约6000个样本将 Qwen3.5-9B 在 SWE-bench Verified 上的 Pass@1 从41.8%提升到56.4%。
**解决的问题**：传统代理强化学习要求训练框架重新实现代理循环，代价高且训练出的代理与部署代理不一致；训练真实代理框架时面临重分词、优势计算、损失归一化和后端调度等挑战。

**核心技术**
- 提出 Harnessed Agentic RL 范式，通过 LLM 代理使原代理框架无需修改即可接入强化学习训练。
- 以约3500行代码实现完整控制平面，包含 API 网关、Rollout 控制器和基于 verl 的定制训练器。
- 引入 Collocated Async RL，让 rollouts 和模型更新共享同一组 GPU，达到约2倍端到端加速。
- 支持将代理作为标准 Kubernetes 作业运行，无需依赖商业沙箱服务。

**关键结果**
- 在 SWE-bench Verified 上，Qwen3.5-9B 的 Pass@1 从41.8%提升到56.4%，绝对提升14.6个百分点，仅使用约6000个训练样本。
- Collocated Async RL 相比同步 RL 实现约2倍端到端加速，且比传统异步 RL 占用更少 GPU。
- 相比样本级处理， rollout 级优势计算和 loss 归一化获得更高的验证奖励和更稳定的策略熵。

**局限与风险**
- 原文未明确说明框架在非编码代理任务或更大规模模型上的泛化能力。
- Collocated Async RL 在更新期间会暂停接收新请求，可能影响实时性。
- 实验仅基于 Qwen3.5-9B 和 SWE-smith 数据集，结果可能不具备普遍性。

**适合阅读**：从事 AI 代理强化学习研究、希望在不修改现有代理框架的情况下训练智能体的研究人员和工程师，以及对轻量级分布式训练框架感兴趣的开发者。

**4. 弹性潜在循环：一种无单环损失的可循环语言模型训练方法**
原题：One Model to Loop Them All: Elastic Latent Recurrence for Language Models
分类：模型训练与推理　推荐：⭐⭐⭐⭐（9.0/10）
来源：arXiv cs.CL　发布时间：2026-10-12
入选理由：消除单循环损耗的弹性隐循环训练，单checkpoint算力换精度，4B/30B MoE十任务实测充分，前沿性强。

**一句话结论**：ELR 通过门控状态更新、优化器步内混合环数和环条件调制，训练出在单环时与非循环同尺寸模型相当、多环时进一步提升的单一检查点。
**解决的问题**：潜在循环语言模型在单环时性能显著低于同尺寸非循环模型（单环税），导致延迟敏感场景下仍需单独训练非循环模型；已有方法无法在不牺牲单环性能的情况下实现弹性深度。

**核心技术**
- 采用自适应增量状态更新：状态沿循环块提议的修改方向按学习到的门控步长更新，而非直接替换；
- 在每个优化器步骤内混合不同环数：在数据并行组中强制旋转部分 rank 始终使用单环，确保单环和多环梯度在同一更新中平均；
- 对每个环进行条件调制：输入环索引和预算，通过 AdaLN/FiLM 风格的调制和低秩适配器使各环可以特化；
- 引入后期混合深度训练与跨环路由重放：在预训练最后四分之一引入混合深度，并用零初始化条件调制保证切换时模型等同于单环检查点；MoE 模型中复用首环专家路由以降低训练开销。

**关键结果**
- 在 4B 密集模型上，单环 ELR 比基线低 0.52 分（十分任务平均），四环高 7.25 分；在 30B-A3B MoE 混合模型上，单环高 1.04 分，四环高 4.75 分。
- 后期混合深度训练（最后四分之一）的估计训练 FLOPs 仅比基线多 16%，而全程混合深度需多 62%，且零初始化条件调制使后期调度优于从头混合训练。
- 跨环路由重放使 MoE 混合深度更新时间减少 11.7%，且准确度无显著变化。
- 基于 ELR 的后训练模型 Koi-4B 在单环时 Artificial Analysis Intelligence Index 估计为 18（与 Qwen3.5-4B 持平），四环时达到 29。

**局限与风险**
- 验证规模有限：核心实验仅在 4B 和 30B-A3B 模型上进行，更大规模的效果未知。
- 跨环路由重放仅在 MoE 模型上评估，未在稠密模型或不同 MoE 配置下验证。
- 单环性能与基线的微小差距（4B 低 0.52 分）仍需在实际部署中权衡，且未讨论对长文本或特定任务的影响。

**5. SWE-Duel：面向编码智能体的自扩展竞技场**
原题：SWE-Duel: Towards a Self-Scaling Arena for Coding Agents
分类：Agent评测　推荐：⭐⭐⭐⭐（8.0/10）
来源：arXiv cs.CL　发布时间：2026-10-12
入选理由：自扩展红蓝互评编码竞技场，任务与Oracle动态生成，11模型1500轮，评测方法创新。

**一句话结论**：提出SWE-Duel，一种自扩展的编码智能体评估机制，通过智能体之间的对抗式互相出题与解题，使任务难度随参与者能力自动提升，且避免测试内容泄露。
**解决的问题**：现有静态编码基准在发布后会泄露到训练数据中，且任务难度固定，导致模型饱和，无法长期可靠评估编码智能体。

**核心技术**
- 设计红蓝对抗回合：红方智能体在真实仓库上实现新功能并植入微妙缺陷，蓝方智能体在不知情的情况下审查并尝试修复，以测试套件通过与否判定胜负。
- 采用三阶段任务生成与验证门控：红方依次完成功能实现、缺陷植入，并通过自我修复门控确保任务可解性。
- 任务在评估时动态创建，缺陷隐藏于新功能中，避免通过回退或运行现有测试发现缺陷。
- 构建开源竞技场工具包，支持从零开始锦标赛或向现有排行榜添加新智能体。

**关键结果**
- 在11个参与者、15个仓库、1500轮比赛中，GPT-5.5配合Codex CLI修复了98.3%的审查缺陷，排名第一。
- Claude Opus 4.8配合mini-swe-agent作为出题方胜率最高，红方胜率为27.3%。
- 同一模型家族内，最新版本创建的任务击败固定参考解题者的频率远高于旧版本（42.9% vs 4.0%），初步显示任务难度随出题能力提升。

**局限与风险**
- 自修复门控可能限制任务难度：出题者必须能盲修自身缺陷，可能排除最具挑战性的任务。
- 参与者需要在多个仓库上进行五轮尝试，计算资源消耗较大。
- 原文未说明对非开源仓库或更大规模仓库的适用性。

**适合阅读**：适合对编码智能体评估、动态基准设计和对抗性任务生成感兴趣的研究人员和工程师。

分类：Agent数据合成　推荐：⭐⭐⭐⭐（8.0/10）

入选理由：学习反馈驱动多智能体数据合成，闭环演化生成空间，τ²-Bench成功率提升13.3点。

**一句话结论**：EvoSyn 是一个多智能体框架，通过结合学习反馈驱动合成空间内适应和扩展，解决反馈到决策的差距，提升任务智能体在应机环境中的表现。
**解决的问题**：现有智能体数据合成方法虽引入环境反馈、数据验证或学习者失败，但存在反馈到决策的差距：观察到的弱点不能直接指明未来合成应如何改变，或当前合成空间能否表示这些弱点。

**核心技术**

- 实现空间内适应，当学习者的弱点已可由现有因素表达时，重新分配合成努力到不足区域。

**关键结果**

**2. 如何构建 MCP 桥接：让云上 AI 代理访问本地 MCP 工具**
原题：How we built an MCP bridge to give our AgentCore-hosted AI agent access to local MCP tools
分类：Agent工具集成　推荐：⭐⭐⭐⭐（8.5/10）
来源：AWS Machine Learning　发布时间：2026-08-05
入选理由：MCP桥接云端Agent与本地工具，创新方案且安全细节好。

**一句话结论**：通过浏览器扩展和本地原生消息桥接，将云端 AgentCore Strands 代理与用户本地的 MCP 服务器安全连接，实现云代理调用本地文件、Excel 等工具。
**解决的问题**：企业级 AI 代理部署在云端，但用户的数据（如 Excel 文件、本地文件系统）仍在本地笔记本电脑上，需要一种安全、低延迟的方式让云端代理调用本地工具，而无需将敏感数据上传到云端或修改 MCP 协议。

**核心技术**
- 在用户本地机器上运行一个 FastMCP 代理桥接（MCP Bridge），它通过标准输入输出（stdio）与本地 MCP 服务器通信，同时通过 Chrome 原生消息协议与浏览器扩展通信。
- 开发一个 Chrome 浏览器扩展，作为双向中继：通过预签名的 WebSocket 连接云端 AgentCore 运行时，并通过原生消息将 MCP JSON-RPC 请求转发给本地 MCP 桥接。
- 云端 AgentCore 运行时托管 Strands 代理，该代理通过 WebSocket 发送工具发现和调用请求，并使用异步 Future 机制实现请求-响应关联，支持并发工具调用。
- 使用 AgentCore SDK 在本地生成 SigV4 签名的预签名 WebSocket URL，确保凭证不离开用户机器，同时处理连接自动续期。

**关键结果**
- 成功实现了云中 AgentCore 代理对本地 Excel 服务器的工具调用，可读取、写入 Excel 工作簿，并返回结构化摘要。
- 该架构无需修改 MCP 协议或现有 MCP 服务器，只需在 mcp.json 中添加一行配置即可接入新的本地工具（如文件系统、Git）。
- 整个消息流中，每一层剥离一个封装（WebSocket 信封 → 原生消息信封 → 原始 JSON-RPC），实现了清晰的分层和协议转换。
- 该模式已用于内部财务 AI 助手，一年内支持超过 41,000 次对话。

**局限与风险**
- 当前安全措施仅包含原生消息来源限制、预签名 URL 过期和进程隔离，生产环境需额外增加认证、载荷签名、文件系统范围限定和审计日志。
- 演示中未实现浏览器操作工具（如 Playwright MCP 的点击、导航等），原文建议未来通过扩展注入实现。
- 桥接进程目前依赖 Python 环境和手动配置，生产分发需打包为独立二进制文件。

**适合阅读**：适合构建企业级 AI 助手、需要云代理安全访问本地资源的架构师和开发者，熟悉 AWS Bedrock、MCP 及浏览器扩展机制者尤佳。

**4. 使用Amazon Bedrock AgentCore时态策略保护AI代理**
原题：Securing AI agents with temporal policies in Amazon Bedrock AgentCore
分类：Agent安全与策略　推荐：⭐⭐⭐⭐（8.0/10）
来源：AWS Machine Learning　发布时间：2026-08-06
入选理由：Bedrock AgentCore时间性策略，增强Agent授权控制，有实际价值。

**一句话结论**：通过AgentCore网关的时态（temporal）策略实现基于会话轨迹的状态化访问控制，防止代理绕过工作流顺序、数据伪造、预算超限等问题。
**解决的问题**：AI代理在运行时动态选择工具调用顺序和参数，传统无状态访问控制无法检测工具调用链中的上下文违规（如订单错误、数据伪造、累积风险），且代理可能规避自主代码内的策略。

**核心技术**
- 在AgentCore网关边界执行时态策略，代理无法篡改或绕过
- 基于会话轨迹（agent trajectory）评估当前请求是否与历史事件存在顺序或数值依赖
- 使用Dogwood治理语言编写策略，支持Cedar兼容及时间条件约束
- 针对不同场景设计7类策略：工作流排序、输入输出完整性、数据新鲜度、会话预算上限、大额交易审批消费、买卖互斥、无交互信任衰减

**关键结果**
- 时态策略可阻止代理跳步（如直接执行交易而跳过读取客户资料），确保工作流顺序
- 防止代理虚构或替换工具调用的参数值（如错误的portfolio_id）
- 通过限制数据有效期（如市场报价30秒内）和会话总金额（6万美元），控制代理的自治风险
- 实现精细化的审批机制（一次审批仅允许一笔大额交易）和自主操作权限随时间衰减

**局限与风险**
- 策略依赖开发人员定义正确的时间窗口和条件，误配置可能导致误拒绝
- 会话轨迹回溯窗口最长24小时，长时运行工作流可能需要额外状态管理
- 原文未说明大规模多代理场景下的性能影响和策略管理复杂度

**适合阅读**：使用Amazon Bedrock构建AI代理的云安全工程师、平台架构师和技术决策者
